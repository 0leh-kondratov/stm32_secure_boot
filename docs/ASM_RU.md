# Ассемблер в проекте: описание и использование

В проекте используется **GNU Assembler** (ARM) для стартового кода. Синтаксис: **unified**, целевой CPU — **Cortex-M7**, режим **Thumb**.

---

## 1. Какие файлы и зачем

| Файл | Назначение |
|------|------------|
| **app/startup_stm32h743xx.s** | Стартап для приложений (demo, lwip, step1, step2 и т.д.). Векторы прерываний, инициализация RAM, вызов `main`. Опционально: раннее зажигание LED2 (PE1). |
| **bootloader/startup_stm32h743xx.s** | Стартап для бутлоадера. То же по структуре, но без лишней периферии: только стек, очистка .bss/.data, задержка и LED1 (PB0), затем `main`. |

Оба файла задают:
- таблицу векторов (первое слово — начальный SP, второе — счётчик программ);
- точку входа `Reset_Handler`;
- заглушки для обработчиков исключений (NMI, HardFault, SysTick, SVC, PendSV и др.).

Линкер помещает секцию `.isr_vector` в начало FLASH (по адресу из скрипта, обычно `0x08000000`), чтобы процессор после сброса загрузил SP и PC из первых двух слов.

---

## 2. Директивы и синтаксис

В начале каждого `.s`:

```asm
.syntax unified   /* единый синтаксис ARM (удобнее для Thumb) */
.cpu cortex-m7
.fpu softvfp     /* софт-эмуляция FPU при необходимости */
.thumb           /* только Thumb-инструкции */
```

- **.global** — экспорт символа для линкера (например `Reset_Handler`, `g_pfnVectors`).
- **.section .isr_vector,"a",%progbits** — секция только для чтения, выровненная, в ней лежит таблица векторов.
- **.word** — одно 32-битное значение (адрес или номер обработчика).
- **.thumb_func** — следующая метка — функция в Thumb (корректный переход с `bx`/`bl`).
- **.weak** — слабый символ: если где-то определён свой `SysTick_Handler`, подставится он.
- **.rept N** / **.endr** — повторить блок из N слов (резерв под векторы 16..255).

Символы `_estack`, `_sbss`, `_ebss`, `_sdata`, `_edata`, `_sidata` задаются **линкер-скриптом** (например `demo.ld`, `app.ld`).

---

## 3. Таблица векторов прерываний (.isr_vector)

Расположение в памяти должно совпадать с тем, что ожидает ядро (часто VTOR = 0x08000000). Порядок слов по ARM:

| Смещение | Содержимое | Описание |
|----------|------------|----------|
| 0x00 | `_estack` | Начальное значение указателя стека (MSP). Берётся из линкера: конец RAM. |
| 0x04 | `Reset_Handler` | Сброс — сюда прыгает ядро после загрузки SP. |
| 0x08 | NMI_Handler | NMI. |
| 0x0C | HardFault_Handler | HardFault. |
| 0x10 | MemManage_Handler | MemManage. |
| 0x14 | BusFault_Handler | BusFault. |
| 0x18 | UsageFault_Handler | UsageFault. |
| 0x1C–0x28 | 0 или зарезервировано | Reserved. |
| 0x2C | SVC_Handler | SVC (используется FreeRTOS для вызова планировщика). |
| 0x30 | DebugMon_Handler | Debug monitor. |
| 0x34 | 0 | Reserved. |
| 0x38 | PendSV_Handler | PendSV (переключение контекста в FreeRTOS). |
| 0x3C | SysTick_Handler | SysTick (тик ОС). |
| 0x40+ | 0 (240 слов) | Внешние прерывания (IRQ0–IRQ239); при необходимости подменяются на реальные обработчики. |

В коде это задаётся последовательностью `.word`; пустые слоты — `.word 0`. Обработчики по умолчанию — метки, ведущие в бесконечный цикл `b .` (или слабые заглушки `b .` для SVC/PendSV/SysTick, чтобы их переопределить в C).

## 4. Reset_Handler: пошагово

Логика одинаковая в app и bootloader; отличия — только «ранний» LED и задержка.

### 4.1 Установка стека

```asm
ldr r0, =_estack
msr msp, r0
```

Указатель стека (MSP) задаётся адресом конца RAM (`_estack` из линкер-скрипта). Без этого любой вызов функции или прерывание приведут к падению.

### 4.2 Ранний LED (опционально)

**app/startup:** включается LED2 (PE1) на NUCLEO — визуально видно, что выполнение дошло до стартапа.

- RCC: `0x58024400` + 0xE0 → AHB4ENR; бит 4 = GPIOE.
- GPIOE: база `0x58021000`; MODER (0x00) — вывод для пина 1; BSRR (0x18) — установка/сброс. На NUCLEO LED активны по низкому уровню: запись в «reset»-бит BSRR гасит, в «set» — зажигает (в коде используется бит 1+16 для выключения по умолчанию или наоборот в зависимости от схемы).

**bootloader/startup:** то же для LED1 (PB0), плюс короткая задержка в цикле, чтобы мигание было заметно после сброса.

### 4.3 Очистка .bss

Неинициализированные глобальные и статические переменные (обнуляемые) лежат в секции `.bss`. Перед вызовом C-кода их нужно обнулить:

```asm
ldr r0, =_sbss      /* начало .bss */
ldr r1, =_ebss      /* конец .bss */
mov r2, #0          /* значение для записи (обязательно!) */
b 2f
1:  str r2, [r0]
    adds r0, r0, #4
2:  cmp r0, r1
    bcc 1b
```

Важно: **r2 должен быть явно обнулён** (`mov r2, #0`). Без этого в .bss попадает мусор и поведение C-кода (в т.ч. FreeRTOS) непредсказуемо.

### 4.4 Копирование .data

Инициализированные данные при загрузке лежат во FLASH (адрес `_sidata`), а при выполнении должны находиться в RAM между `_sdata` и `_edata`:

```asm
ldr r0, =_sdata
ldr r1, =_edata
ldr r2, =_sidata
b 4f
3:  ldr r3, [r2]
    str r3, [r0]
    adds r0, r0, #4
    adds r2, r2, #4
4:  cmp r0, r1
    bcc 3b
```

Цикл копирует слова из FLASH в RAM. Если размер .data нулевой, цикл не выполняется.

### 4.5 Переход в main

```asm
bl main
b .
```

Вызов `main` и бесконечный цикл, если `main` когда-либо вернётся (по стандарту не должна).

## 5. Обработчики исключений

Все обработчики по умолчанию — заглушки:

```asm
.thumb_func
Default_Handler:
NMI_Handler:
HardFault_Handler:
...
    b .    /* бесконечный цикл */
```

Имена совпадают с векторами. В C можно переопределить, например:

- **SysTick_Handler** — в демо с FreeRTOS вызывается `xPortSysTickHandler()` из `main_freertos.c`.
- **SVC_Handler**, **PendSV_Handler** — подменяются макросами в `FreeRTOSConfig.h` на `vPortSVCHandler` и `xPortPendSVHandler` (порт FreeRTOS).

Слабые метки (`.weak SVC_Handler` и т.д.) позволяют линкеру подставить сильные символы из C/другого asm.

## 6. Сборка в Makefile

Пример (demo):

```makefile
$(BUILD)/startup.o: $(TOP)/app/startup_stm32h743xx.s | $(BUILD)
	$(CC) -mcpu=cortex-m7 -mthumb -c -o $@ $<
```

- Тот же компилятор, что и для C (`arm-none-eabi-gcc`), в режиме ассемблера (`-c`, исходник `.s`).
- Флаги `-mcpu=cortex-m7 -mthumb` должны совпадать с целевым ядром и режимом в `.cpu`/`.thumb`.
- Объект `startup.o` добавляется в список при линковке; линкер-скрипт помещает `.isr_vector` в начало образа.

Бутлоадер собирает свой `bootloader/startup_stm32h743xx.s` по аналогичному правилу.

---

## 7. Как добавить свой .s

1. Создайте файл, например `app/demo/extra.s`, с теми же директивами в начале (`.syntax unified`, `.cpu cortex-m7`, `.thumb`).
2. Объявите глобальные метки: `.global My_Func`.
3. В Makefile добавьте объект в переменную с остальными `.o` и правило:
   ```makefile
   $(BUILD)/extra.o: $(TOP)/app/demo/extra.s | $(BUILD)
   	$(CC) -mcpu=cortex-m7 -mthumb -c -o $@ $<
   ```
4. В C объявите прототип, например `void My_Func(void);`, и вызывайте как обычную функцию.

Инлайн-ассемблер в C тоже допустим: `__asm volatile("nop");` или расширенный `asm` с операндами — без правок Makefile.

## 8. Связь с линкер-скриптом

В `demo.ld` (и аналогах) задаётся:

- **MEMORY** — FLASH и RAM, их размеры.
- **_estack** — обычно `ORIGIN(RAM) + LENGTH(RAM)`.
- **SECTIONS**:
  - `.isr_vector` — первая в FLASH, `KEEP(*(.isr_vector))`.
  - `.text` — код.
  - `.data` — инициализированные данные в RAM с `LOADADDR(.data)` для копирования.
  - `.bss` — неинициализированные данные в RAM; метки `_sbss`, `_ebss`, `_sdata`, `_edata`, `_sidata` выводятся скриптом.

Без корректных `_sbss`/`_ebss`/`_sdata`/`_edata`/`_sidata` циклы в Reset_Handler будут работать неверно или затирать не ту память.

---

## 9. Кратко

| Элемент | Назначение |
|--------|------------|
| **.isr_vector** | Таблица векторов: SP, Reset, NMI, Fault, SVC, PendSV, SysTick, IRQ. |
| **Reset_Handler** | SP → инициализация (опц. LED) → обнуление .bss → копирование .data → `main`. |
| **.bss** | Обязательно обнулять; в цикле использовать регистр, явно установленный в 0. |
| **.data** | Копировать из FLASH (_sidata) в RAM (_sdata.._edata). |
| **Обработчики** | Заглушки `b .`; SVC/PendSV/SysTick переопределяются в C (FreeRTOS). |
| **Сборка** | `$(CC) -mcpu=cortex-m7 -mthumb -c` для каждого `.s`; объект участвует в линковке. |

Дополнительно: [ARM Cortex-M7 Generic User Guide](https://developer.arm.com/documentation/dui0646/latest), раздел про исключения и векторную таблицу.
