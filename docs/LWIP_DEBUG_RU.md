# Как смотреть, почему app/lwip не работает

Реализация app/lwip приведена к официальному примеру ST **LwIP HTTP Server Netconn RTOS** (каталог `stm32_eth_files`): те же MPU-регионы для ETH DMA и LwIP heap, размещение секций в D2 SRAM (0x30000000), инвалидация D-Cache при приёме, поток контроля линка и DHCP.

## 1. Подключить UART и открыть терминал

- **Порт:** на NUCLEO-H743ZI лог идёт по **USART3** (PD8/PD9), часто проброшен через **ST-Link VCP**. В Linux порт обычно `/dev/ttyACM0` или `/dev/ttyUSB0`.
- **Скорость:** 115200 8N1.

Узнать порт и открыть терминал:

```bash
# Узнать порт (после подключения платы по USB)
ls -la /dev/ttyACM* /dev/ttyUSB* 2>/dev/null
# или
st-info --probe
```

Открыть терминал (подставьте свой порт):

```bash
minicom -D /dev/ttyACM0 -b 115200
# или
screen /dev/ttyACM0 115200
```

В minicom: **Ctrl+A O** → Serial port setup → **E** (Bps/Par/Bits) → 115200 8N1.

**Перед прошивкой lwip** откройте терминал и оставьте его открытым, затем сделайте Reset платы (кнопка или питание).

---

## 2. Что вы должны увидеть по шагам

При успешной работе в UART появляется **в таком порядке**:

| Что видите | Значение |
|------------|----------|
| **`lwip: boot`** | Плата запустилась, такты и UART работают. Если этого нет — проблема до планировщика (часы, порт, прошивка не туда). |
| **`app/lwip: FreeRTOS + Ethernet`** | Запустилась задача StartDefaultTask, инициализирован лог. |
| **`--- TCP/IP ---`** и далее IP/Netmask/Gateway/MAC | LwIP и сеть подняты. При DHCP сначала может быть "Link down (no IP)", через несколько секунд — адрес. |

Дополнительно: **LED1 (PB0)** сразу после сброса должен **гореть** (включён в самом начале `main()`); после старта планировщика начнёт **мигать** примерно раз в 0.5 с.

---

## 3. По симптомам: что проверить

### В UART вообще ничего нет

1. **Проверить LED1 (PB0):** в `main()` самым первым делом LED1 зажигается через регистры (до MPU и HAL).
   - **LED1 горит** — выполнение доходит до `main()`, прошит образ lwip. Тогда проблема между ранним LED1 и UART: `HAL_Init()`, `SystemClock_Config()` или `log_init()`/`log_puts()`. Проверить, что терминал на **115200**, порт **USART3** (часто через ST-Link VCP — `/dev/ttyACM0`).
   - **LED1 не горит** — до `main()` не дошли или прошит не тот образ. Выполнить `make flash-lwip` и сбросить плату. Убедиться, что прошивка идёт в **0x08000000** (не в область бутлоадера).
2. **Убедиться, что UART и плата живые:** прошейте step1 и откройте тот же порт 115200:
   ```bash
   make step1 && make flash-step1
   ```
   Должны идти строки "Step 1: OK". Если и step1 молчит — смотреть порт (ttyACM0/ttyUSB0), 115200, BOOT0=0, питание.
3. **После step1 снова прошить lwip** и сбросить плату — смотреть, появилось ли хотя бы `lwip: boot`.

### Есть только `lwip: boot`, дальше тишина

Значит зависание в планировщике или в задаче до первого `log_puts`. Возможные места: `osKernelStart()`, начало `StartDefaultTask` до `log_init()` (в задаче вызывается второй раз — не страшно), или падение до входа в задачу. Имеет смысл смотреть под отладчиком (GDB + st-util), поставить breakpoint в `StartDefaultTask`.

### Есть `app/lwip: FreeRTOS + Ethernet`, но нет блока TCP/IP

Зависание или сбой при инициализации LwIP/сети: `tcpip_init()`, `Netif_Config()`, или ожидание линка/DHCP. Проверьте:

- Кабель Ethernet подключён к плате и к активному порту (роутер/компьютер).
- Индикаторы линка на порту (если есть).

При статическом IP (если позже переключите в коде на статику) блок TCP/IP появится сразу после поднятия интерфейса.

### LED1 не мигает

Либо планировщик не доходит до задачи LED1, либо задача не создаётся. По логу: если есть "app/lwip: FreeRTOS + Ethernet", задача стартовала; если и TCP/IP блок есть — значит, до LED1 код доходит. Если LED1 всё равно не мигает — проверить пин (PB0 на данной плате).

## 4. Отладка под GDB (по желанию)

1. Запустить сервер: `st-util`.
2. В другом терминале:  
   `arm-none-eabi-gdb build/lwip/lwip.elf`  
   затем: `target extended-remote :61234`, `load`, `continue`.
3. В Cursor/VS Code можно использовать конфиг для "Debug demo (ST-Link, железо)", подставив путь к `build/lwip/lwip.elf`.

Так можно поставить breakpoint в `main`, в `StartDefaultTask`, в `log_tcpip_params` и смотреть, на каком шаге выполнение останавливается.

---

## 5. Краткий чек-лист

- [ ] Плата NUCLEO-H743ZI, BOOT0 = 0, питание по USB.
- [ ] Прошивка: `make lwip && make flash-lwip`.
- [ ] После Reset **LED1 горит** (включён в начале main; если не горит — образ не запускается).
- [ ] Терминал открыт на правильном порту (часто `/dev/ttyACM0`), 115200 8N1.
- [ ] В терминале вижу хотя бы `lwip: boot`.
- [ ] Ethernet подключён; при DHCP подождать несколько секунд для появления IP в логе.

Если step1 по UART работает, а после прошивки lwip нет даже `lwip: boot` — значит, образ lwip не запускается (адрес прошивки, вектор сброса или зависание до первого вывода).
