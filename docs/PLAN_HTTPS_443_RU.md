# План: HTTPS-сервер на порту 443 (Netconn + mbedTLS) и память 128 KB

Цель: сервер, отвечающий на GET-запросы по HTTPS (порт 443) с использованием mbedTLS; куча FreeRTOS не менее 128 KB для LwIP и mbedTLS.

---

## 1. Память (configTOTAL_HEAP_SIZE ≥ 128 KB)

**Задача:** обеспечить минимум 128 KB кучи FreeRTOS для LwIP, mbedTLS и задач.

**Файлы и правки:**

| Файл | Текущее значение | Действие |
|------|------------------|----------|
| `FreeRTOS/Source/include/FreeRTOSConfig_lwip.h` | `40 * 1024` (40 KB) | Заменить на `(128 * 1024)` |
| `app/lwip_zero/Inc/FreeRTOSConfig.h` (если используется для сборки LwIP) | `40 * 1024` | То же: `(128 * 1024)` |

**Проверка:** после сборки LwIP-образа убедиться, что линкер не ругается на переполнение RAM (участок кучи в RAM). При необходимости в линкере увеличить размер heap/stack или оставить 128 KB в пределах доступной RAM (у H743 достаточно).

---

## 2. HTTPS: сервер на 443 с mbedTLS

**Идея:** сервер в стиле Netconn (accept → read → parse GET → send response), но транспорт — TLS на порту 443 через LwIP **altcp_tls** (под капотом mbedTLS).

**Важно:** в LwIP Netconn API не умеет TLS «из коробки». TLS делается через **altcp** (application-layer TCP): поднимаем слушающий **altcp_pcb** с типом **altcp_tls** на порту 443, по accept получаем уже TLS-соединение, дальше читаем/пишем через altcp_* — логика как у HTTP Netconn (парсинг GET, отправка ответа).

---

## 3. Пошаговый план выполнения

### Шаг 1. Куча 128 KB

- В `FreeRTOSConfig_lwip.h` и при необходимости в `app/lwip_zero/Inc/FreeRTOSConfig.h` выставить:
  - `configTOTAL_HEAP_SIZE ((size_t)(128 * 1024))`
- Пересобрать LwIP-образ, проверить линкер и работу (ping, существующий HTTP при наличии).

### Шаг 2. Подключение mbedTLS

- **Источник mbedTLS:** STM32CubeH7  
  `Middlewares/Third_Party/mbedtls/` (или аналог из другого репозитория проекта).
- В сборку добавить:
  - пути include: `Middlewares/Third_Party/mbedtls/include`, `Middlewares/Third_Party/mbedtls/library`;
  - нужные `mbedtls_*.c` по минимальной конфигурации для TLS-сервера (см. `mbedtls_config.h` в Cube; обычно: ssl, ssl_tls, x509, pk, pk_wrap, cipher, md, etc.).
- Убедиться, что в проекте один общий `mbedtls_config.h` (можно из Cube), без лишних фич для экономии Flash/RAM.

### Шаг 3. LwIP: altcp + altcp_tls_mbedtls

- В **lwipopts.h** (или в опциях LwIP, которые использует ваш образ):
  - `LWIP_ALTCP 1`
  - `LWIP_ALTCP_TLS 1`
  - `LWIP_ALTCP_TLS_MBEDTLS 1`
- В сборку добавить исходники LwIP:
  - `altcp.c`
  - из `lwip/apps/altcp_tls/`: `altcp_tls_mbedtls.c`, при необходимости `altcp_tls_mbedtls_mem.c` (если используется свой аллокатор под mbedTLS).
- Include-путь до mbedTLS должен быть доступен при компиляции этих файлов.

### Шаг 4. Сертификат и ключ сервера

- Для теста достаточно самоподписанного сертификата и ключа (PEM или DER, в зависимости от того, что принимает altcp_tls_mbedtls).
- Варианты:
  - Сгенерировать на ПК (OpenSSL) и вшить в прошивку в виде C-массивов (или в отдельный .c/.h).
  - Взять готовые тестовые сертификат/ключ из примеров mbedTLS/Cube и встроить в проект.
- В коде инициализации TLS-сервера передать в mbedTLS/LwIP эти данные (сертификат + приватный ключ).

### Шаг 5. Задача HTTPS-сервера (порт 443)

- В отдельном модуле (например `https_server_netconn.c` или `https_server_altcp.c`):
  - Запуск в контексте потока TCPIP (или отдельной задачи FreeRTOS, вызывающей только LwIP-API из одного потока).
  - Создать слушающий **altcp_pcb** для порта 443 через **altcp_tls** (тип TLS, конфиг mbedTLS: сертификат, ключ, опции верификации).
  - В цикле: **altcp_accept** → новый pcb (уже TLS); читать данные через **altcp_recv** (в callback или в блокирующем режиме, если API позволяет), разобрать первую строку запроса и проверить, что это `GET /` или `GET /...`.
  - Сформировать минимальный HTTP-ответ, например:
    - `HTTP/1.1 200 OK\r\nContent-Type: text/html; charset=utf-8\r\nConnection: close\r\n\r\n`
    - тело: простая HTML-страница или текст `OK`.
  - Отправить через **altcp_write**, закрыть соединение (**altcp_close**), освободить pcb.
- Приоритет задачи — по аналогии с существующим HTTP Netconn (например нормальный/выше нормального), размер стека — с запасом под mbedTLS (например 2–4 KB).

### Шаг 6. Инициализация в main/LwIP

- После инициализации LwIP и netif (и при необходимости DHCP) вызвать функцию инициализации HTTPS-сервера (создание задачи/потока, которая слушает 443 через altcp_tls).
- Убедиться, что порт 443 не занят другим кодом.

### Шаг 7. Сборка и проверка

- Сборка: целевой Makefile/IDE должен включать mbedTLS, altcp, altcp_tls_mbedtls, новый модуль HTTPS-сервера и обновлённый FreeRTOSConfig (128 KB).
- Проверка:
  - Плата в сети (статический IP или DHCP).
  - В браузере: `https://<IP_платы>` (или `https://<IP>:443`). Ожидается предупреждение о самоподписанном сертификате — принять исключение, после чего должна открыться страница с ответом на GET (например «OK» или минимальная HTML-страница).

---

## 4. Риски и упрощения

- **RAM/Flash:** mbedTLS и TLS увеличивают потребление. 128 KB кучи — минимум; при нехватке можно поднять до 160–192 KB, если линкер и RAM позволяют.
- **Совместимость API:** в LwIP версии из Cube/вашего дерева точные имена и сигнатуры altcp_tls (создание слушателя, привязка сертификата) могут отличаться — ориентироваться на заголовки `lwip/apps/altcp_tls.h` и `altcp_tls_mbedtls*.h` в вашем клоне LwIP.
- **Упрощение на первом этапе:** можно сделать только TLS listen на 443 и ответ одной фиксированной строкой на любой GET, без разбора URL и без файловой системы.
