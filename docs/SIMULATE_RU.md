# Эмуляция бутлоадера в Renode

Скрипт **simulate.resc** запускает образ бутлоадера в эмуляторе [Renode](https://renode.io/) на платформе STM32H743 (Cortex-M7, flash, RAM, USART3 и др.). Удобно проверять логику без платы.

---

## 1. Установка Renode

- **Linux (Debian/Ubuntu):**  
  `sudo apt install renode`  
  или скачайте с [renode.io](https://renode.io/).
- **macOS / Windows:** установщик с сайта Renode.

Проверка: `renode --version`.

---

## 2. Сборка и запуск

Из корня проекта:

```bash
make -f bootloader/Makefile all
make signed-app
renode simulate.resc
```

Renode подхватит платформу из своего каталога (`platforms/cpus/stm32h743.repl`), загрузит **build/bootloader/bootloader.elf** и **build/app/signed_app.bin** по 0x08010000. Без подписанного приложения в эмуляции бутлоадер выдаст «FAIL: bad magic» и остановится.

---

## 3. Что ожидать

- После `start` CPU начинает выполнение с Reset_Handler, затем `main()`.
- Бутлоадер включает LED1, вызывает `log_init()` и пишет в USART3. В окне **usart3** должны появиться строки вида `[boot] Secure bootloader`, `[boot] UART 115200 OK` и т.д.
- Проверка подписи в эмуляции читает память по адресу образа приложения (0x08010000). Если там пусто или мусор — проверка может не пройти (stub принимает любой образ, но чтение за границами flash может вести себя иначе). Для «чистой» проверки логов достаточно.

---

## 4. Ограничения эмуляции

- Модель STM32H743 в Renode не полная: часть периферии может отсутствовать или вести себя иначе, чем на железе.
- Тактирование и тайминги отличаются от реальной платы — задержки и UART могут вести себя по-другому.
- HASH (аппаратный SHA) и крипто-блоки могут быть не реализованы; при включении реальной ECDSA (без stub) эмуляция может не дойти до проверки подписи.

Эмуляция подходит для отладки потока управления (вход в main, логи, переход в приложение при успешной проверке) без платы.

---

## 5a. Проверка эмуляции на demo (demo.resc)

Чтобы проверить Renode на **простом рабочем образе** без бутлоадера и подписи, используйте **demo.resc** — тот же standalone demo (3 LED + UART), что и на плате:

```bash
make demo
renode demo.resc
```

В окне **usart3** должны появиться строки вида:
- `Demo: LEDs + log (NUCLEO-H743ZI2)`
- `LED1=ON LED2=OFF LED3=OFF` и далее по кругу.

GDB-сервер для demo слушает порт **3334** (чтобы не пересекаться с simulate.resc на 3333). Подключение: `target remote :3334`. В Cursor можно выбрать конфигурацию **Debug demo (Renode)** после запуска `renode demo.resc`.

**GDB для demo (кратко):**
```bash
arm-none-eabi-gdb build/demo/demo.elf
(gdb) target remote :3334
(gdb) break main
(gdb) continue
```

**Как увидеть состояние LED в эмуляции:**
1. **В окне usart3** — demo уже выводит строки `LED1=ON LED2=OFF LED3=OFF` и т.д. (функция `log_led_state` в app/demo/main.c).
2. **В мониторе Renode** (консоль, где запущен renode) можно прочитать регистр GPIO ODR (Output Data Register) — по нему видно текущий уровень на выходах:
   - `(machine-0) sysbus ReadDoubleWord 0x58020414` — **GPIOB ODR**: бит 0 = LED1 (PB0), бит 14 = LED3 (PB14); значение 1 = выход высокий (LED горит).
   - `(machine-0) sysbus ReadDoubleWord 0x58021014` — **GPIOE ODR**: бит 1 = LED2 (PE1); 1 = горит.
   Пример: если первая команда вернула `0x4001`, то биты 0 и 14 установлены → LED1 и LED3 горят.

## 5. Дополнительно

- В **simulate.resc** закомментирован пример **AddHook** на вход в `main` — можно раскомментировать для отладочного вывода при входе в main.
- Путь к ELF: `@build/bootloader.elf` — относительно каталога, из которого запущен Renode (запускайте из корня проекта).

**GDB:** в скрипте включён GDB-сервер на порту **3333**. Сначала запустите `renode simulate.resc`, затем подключите отладчик: `arm-none-eabi-gdb build/bootloader.elf`, в GDB: `target remote :3333`, `break main`, `continue`. Подробнее — раздел «9. Отладка в Renode (GDB)» в [DEBUG_RU.md](DEBUG_RU.md). В Cursor/VSCode можно выбрать конфигурацию **Debug bootloader (Renode)** и нажать F5 (Renode должен быть уже запущен).

## 6. «FAIL: bad magic» на плате

Если такой лог идёт с **реальной платы**, по адресу 0x08010000 во flash нет образа с заголовком (magic `BOOT`). Нужно прошить **объединённый** образ (бутлоадер + приложение), а не только бутлоадер:

```bash
./scripts/flash.sh
```

Он собирает бутлоадер, подписывает приложение и записывает в flash один файл: первые 64 KB — бутлоадер, далее с 0x08010000 — заголовок и приложение. После этого при Reset проверка подписи должна пройти (при USE_ECDSA_STUB — всегда) и выполнение перейдёт в приложение.
